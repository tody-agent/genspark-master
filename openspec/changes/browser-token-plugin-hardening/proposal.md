# Proposal: Browser-Token Plugin Hardening

Generated by: cm-brainstorm-idea
Date: 2026-08-05

## Why we're doing this

### Qualified Problem

For developers and AI-agent users who want Genspark chat and image access without managing a Genspark API key, the current `genspark-master` workspace promises a browser-token gateway but is not a complete installable Codex plugin. Missing runtime modules, absent plugin metadata, inconsistent packaging, and weak session-file protections prevent the existing capabilities from being installed and trusted reliably.

Unlike the official `@genspark/cli`, which persists an API key after browser login, this project will retain browser-derived cookies and reCAPTCHA tokens as its only Genspark authentication material. It will adopt the official CLI's agent-friendly command and output conventions while keeping a smaller, explicit capability surface.

### Root Causes

1. Runtime and packaging artifacts drifted out of sync: three referenced modules and the Codex manifest are absent.
2. Installation, skills, and test-gate paths were developed independently and do not form one verified release flow.
3. Credential persistence predates atomic/private-write and path-containment requirements.

### Impact if not addressed

- Users cannot rely on a clean installation or MCP startup.
- Browser tokens are stored with weaker filesystem guarantees than necessary.
- Documentation overstates capabilities that the checked-in source cannot currently execute.
- Adding official-CLI-like features before restoring the core would compound drift.

## What's changing

### Options evaluated

- Harden the existing browser-token core and adopt agent-native CLI contracts: selected.
- Wrap the official npm CLI: rejected because its authentication persists an API key.
- Port all official Tool API capabilities onto internal browser endpoints: rejected due scope and maintenance risk.

### Recommendation

Restore and secure the existing Python runtime first, package it as `genspark-master`, and add only the official CLI patterns that improve agent use without changing authentication: `gsk` alias, capabilities, doctor diagnostics, clean stdout/stderr, coherent extras, and standardized skills.
